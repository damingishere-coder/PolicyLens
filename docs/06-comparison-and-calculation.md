# 比较与确定性计算

## 比较前提

对比不是把不同产品放进同一张表就完成。系统先建立 `ComparisonCase`，固定被保险条件、司法辖区、预算、缴费期、保障/领取起点、期限、币种、汇率日期和是否要求保证领取。无法对齐时，必须显示“不可直接比较”及原因。

## 展示层次

每个比较结果按以下顺序展示：

1. 合同保证利益；
2. 非保证利益为零的底线情景；
3. 非保证中档/高档等演示情景；
4. 费用、退保、流动性、续保和限制；
5. 来源完整度、冲突和已过期项；
6. AI 对差异的解释草稿。

产品排序默认不使用综合分。若用户启用权重，UI 必须展示权重、归一化方法和排序敏感性，并允许切回原始指标。

## 现金流约定

- 从家庭流出的保费、费用和税费为负数；收到的领取、赔付、退保或身故利益为正数。
- 每条现金流包含日期、币种、类型和保证属性。
- 现金价值是某时点退出价值，不与同一时点继续持有后的未来领取重复累计。
- 身故利益与生存领取按互斥生命情景计算，不能在同一路径双算。
- 内部使用高精度十进制；只在展示层按币种规则四舍五入。

## XIRR

对不等间隔现金流求解：

```text
0 = Σ CF_i / (1 + r)^((date_i - date_0) / 365)
```

实现要求：

- 至少存在一笔正现金流和一笔负现金流，否则结果为“不适用”。
- 使用有界求根并记录容差、最大迭代次数和算法版本。
- 检测可能的多重根或无解情形，不强行返回单一数字。
- 单元测试与独立工具/参考样例交叉验证。
- 结果显示为“基于当前现金流假设的年化内部收益率”，不能描述为保证收益率，除非全部现金流均为合同保证且情景成立。

## 回本与寿命情景

“回本”至少提供两种口径：累计已领取首次不低于累计保费；领取加当时可退出现金价值首次不低于累计保费。界面必须明确当前使用哪一种。

养老方案使用用户可配置的多个寿命年龄点，不把任何单一年龄当预测。每个情景独立计算累计领取、现金价值、身故利益、保证领取余额和 IRR。

## 保证与非保证

- 保证/非保证属性来自有证据的字段，不通过产品名称猜测。
- 分红、万能账户非最低保证部分、历史实现率和销售演示默认为非保证。
- “非保证为零”是基础压力情景，必须始终可见。
- 演示档位只按原文展示，不跨产品擅自统一成相同概率。

## 汇率情景

跨币种比较保留原币结果，并提供独立的换算视图。换算必须记录汇率值、汇率日期、来源和情景标签。历史汇率不能冒充未来汇率；用户可设置升值、基准、贬值情景，但它们都标为假设。

## 保障类产品

医疗、意外、重疾和宠物险不以 IRR 排序。比较维度包括责任定义、共享限额、免赔、比例、等待期、医院/地区/职业/品种限制、既往情况、续保、费率变化、除外和证据完整度。

## 结果可复现性

每次计算保存输入快照、产品版本、算法版本、时区和汇率假设。报告提供机器可读 JSON/CSV 和人类可读公式说明。修改任一事实或假设后生成新结果，不覆盖旧结果。
