# 隐私、安全与本地存储

## 威胁模型

主要风险包括：误把私人文件提交到公开 GitHub；其他 Windows 用户读取数据目录；恶意 PDF/网页内容利用解析器；localhost 服务被非预期网页或本地进程调用；日志/备份/导出泄露；AI 调用发送过多资料。

V1 不声称防御已控制当前 Windows 账户的高级攻击者。系统安全依赖 Windows 账户、设备磁盘加密和及时更新，同时通过最小权限与数据最小化减少影响。

## 数据分类

| 级别 | 示例 | 默认处理 |
|---|---|---|
| Public | 源代码、公开产品链接、合成 fixture | 可进入 GitHub |
| Internal | 本地设置、无个人关联的研究笔记 | 本地保存，导出前复查 |
| Sensitive | 家庭关系、保单元数据、财务目标、宠物健康情况 | 加密字段、禁止遥测和 GitHub |
| Restricted | 原始保单、证件/联系方式、详细健康资料、密钥 | 私有 vault、最小采集、默认不进 AI |

## 存储设计

- 默认数据目录位于 Windows 当前用户的应用数据目录，使用仅当前用户可访问的 ACL。
- 研究数据库与家庭数据库分离；高敏感值在应用层使用 AES-GCM 等认证加密。
- 随机 256 位数据加密密钥（DEK）负责加密敏感字段和 vault 对象。
- 日常本机解锁时，由 Windows 当前用户的 DPAPI 包装 DEK。DPAPI 包装只用于当前机器、当前用户，不作为便携备份密钥。
- 手工便携备份要求至少 12 个字符的恢复密码：使用 Argon2id（基线 `m=65536 KiB, t=3, p=1`，每份备份使用新的 16 字节随机盐）派生 KEK，再以 AES-256-GCM 和新的 12 字节随机 nonce 包装 DEK。备份中保存版本化 KDF 参数、盐、nonce 和密钥密文，不保存恢复密码。
- 原始文件按内容哈希存入加密 vault；数据库保存逻辑 ID，不依赖原始绝对路径。
- 服务终止或 vault 锁定后清除内存中的解密密钥和临时明文。

加密实现必须使用成熟库和独立 nonce，不自创密码算法。若某平台依赖无法可靠打包，加密功能不得以“已保护”名义降级；应用应阻止导入或明确要求用户确认风险。

跨机器恢复只能依赖恢复密码包装，不依赖原电脑的 DPAPI 数据。恢复成功后，同一个 DEK 由新电脑当前用户的 DPAPI 重新包装。恢复密码丢失意味着无法在另一台电脑恢复，UI 必须在创建备份时明确提示并要求完成一次密码校验。

## GitHub 防泄漏

- `.gitignore` 排除家庭数据目录、数据库、原始资料、备份、导出、日志、密钥和工作文件。
- 提交前执行敏感路径、密钥模式、个人标识和大文件扫描。
- 测试只使用明显标记为 synthetic 的虚构人员、机构、保单号和金额。
- 本地测试和未来 CI 都不得上传数据库、截图、失败日志或测试报告中的私人数据。
- 一旦发现误提交，停止 push；若已公开，按泄漏事件处理，不能只删除最新文件假装历史中不存在。

## AI 数据外发

Codex 分析是可选联网处理，不等同离线计算。每次调用前显示白名单载荷的完整发送预览；用户取消时不发送。载荷只能由允许字段直接构造，不能先序列化家庭对象再做删除式脱敏。调用审计只保存哈希和结构化元数据。

一次性工作目录和 `--sandbox read-only` 不是保密边界。PolicyLens 必须假设 Codex 子进程拥有当前 Windows 用户的读取能力，不能声称它技术上无法读取其他本地文件。首次交付通过不传路径、不传原文档、限制证据片段和逐次确认降低风险；强操作系统级隔离属于后续独立安全项目。

## 文件与解析安全

- 只接受 allowlist 类型，校验文件签名而非只看扩展名。
- 设置单文件、页数、解压后大小和解析时间上限，防止压缩炸弹和资源耗尽。
- 首次交付的文本型 PDF 只在 localhost 本地服务中解析，并执行类型、大小和页数限制；解析器进程级隔离作为后续加固项，OCR 仍必须保持本地处理。
- 不执行附件脚本、宏、嵌入文件或外部链接。
- 网页快照按不可信内容处理，不能影响系统提示或启动本地命令。

## 本地 API 与浏览器

- 只监听 loopback；端口由 RunDock 启动参数指定，当前首次交付端口为 `8768`。
- 页面与 API 同源；每次启动生成新的签名会话，使用 HttpOnly、SameSite=Strict Cookie 与 CSRF 校验。
- 页面使用严格 CSP，不加载任意远程脚本，不拥有 Node、shell 或任意本地文件路径权限。
- API 使用明确 Schema，拒绝额外字段、客户端指定的服务端文件路径与路径穿越。
- 日志采用字段 allowlist，默认不记录请求体、证据原文和绝对私人路径。

## 导出与删除

导出默认先预览敏感字段，文件名不包含成员姓名。私人报告保存到用户选择的位置，并显示“该文件已离开受保护数据目录”。删除先进入本地回收/隔离状态；永久删除必须明确确认，并说明备份可能仍包含副本。

## 安全验收门槛

- 能证明私人档案、数据库、vault 和导出不在 Git 跟踪列表。
- 浏览器页面无 Node 全局对象，无法调用任意 shell。
- loopback API 缺少/伪造会话或 CSRF、使用非同源 Origin 时拒绝请求。
- 日志、崩溃和 AI 失败场景中无敏感正文。
- 同机可由 DPAPI 解锁；另一台 Windows 电脑可用正确恢复密码恢复并重新绑定 DPAPI。
- 错误密码、篡改备份和版本不兼容在修改当前数据前失败。
- 备份恢复过程没有明文临时副本残留。
