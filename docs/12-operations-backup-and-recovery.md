# 运行、备份与恢复

## 数据目录

RunDock 首次启动本地服务时创建数据目录，不把数据写入 Git 工作区。建议结构：

```text
PolicyLens/
  databases/
  vault/
  backups/
  exports/
  logs/
  temp/
```

设置页展示每个目录用途和占用空间。路径变更采用复制、校验、切换三阶段流程；失败时继续使用原目录。

## 日志

- 默认 INFO，轮转并限制保留天数和总大小。
- 只记录事件 ID、模块、耗时、错误类别和脱敏路径标识。
- 不记录请求体、证据原文、完整文件名、家庭字段、AI 提示、环境变量或认证信息。
- 用户导出诊断包前显示文件清单并再次运行敏感扫描。

## 备份

备份包包含数据库、vault 对象、Schema 版本和清单哈希，不包含应用程序。数据由随机 256 位 DEK 加密；便携备份使用至少 12 个字符的恢复密码，经 Argon2id（基线 `m=65536 KiB, t=3, p=1`，16 字节随机盐）派生 KEK，再以 AES-256-GCM 和 12 字节随机 nonce 包装 DEK。每份备份使用新的盐和 nonce。备份清单保存版本化 KDF 参数、盐、nonce、密钥密文和数据完整性信息，绝不保存恢复密码或明文 DEK。

首次交付支持手工备份和恢复；本地定时提醒在后续 V1 增量开放。服务先在私有备份目录生成并验证加密包，再通过浏览器下载；失败不能破坏上一份成功备份。恢复包通过浏览器上传到随机临时路径，验证结束后删除。V1 不默认上传 OneDrive、网盘或其他云服务。若用户把下载文件放入云同步位置，设置页明确提示数据将离开纯本地边界。

Windows DPAPI 仅包装当前安装的本机 DEK 缓存，不写入便携恢复链路，也不承诺能在另一台电脑解密。

## 恢复

1. 读取备份清单并验证格式、Schema 版本和外层完整性。
2. 用户输入恢复密码；由 Argon2id 派生 KEK 并尝试解开 DEK。
3. 在独立临时目录验证数据库和 vault，不覆盖当前数据。
4. 显示将恢复的记录、来源和冲突摘要。
5. 为当前数据生成安全快照。
6. 原子切换恢复数据并运行完整性检查。
7. 用新电脑当前用户的 DPAPI 重新包装 DEK。
8. 任一步失败都回到切换前状态，并保存不含敏感正文的诊断事件。

恢复演练必须使用合成数据；测试“创建 → 设置并校验恢复密码 → 备份 → 在另一 Windows 用户/测试机恢复 → 重新绑定 DPAPI → 比对哈希”的完整闭环。错误密码或篡改备份不得产生部分恢复数据。

## 数据库迁移

每次迁移前检查磁盘空间并创建迁移备份。迁移脚本必须幂等或明确记录已执行版本。启动检测到未知的新版本数据库时不得降级写入，只能提示使用匹配版本。

## RunDock 运行

- RunDock 使用项目虚拟环境中的 Python 启动 `scripts/serve.py`，工作目录固定为项目根目录。
- 只传入 `127.0.0.1` 和经冲突检查的固定端口；当前首次交付使用 `8768`，不监听局域网地址。
- 更新代码或依赖后先完成构建与测试，再由 RunDock 重启该单一服务；不得影响其他 RunDock 项目。
- 运行验收必须同时核对 RunDock 记录、监听 PID/命令行、父进程链、`/health` 响应和实际浏览器页面。

## 崩溃恢复

导入和生成任务写入检查点；重启后区分可安全继续、可重新运行和必须人工复核的任务。未知远程状态（例如 Codex 进程异常终止）不能自动重试，以免重复发送材料。

## 更新与停用

- 自动更新不是 V1 必须项；代码与依赖更新由本机受控执行。
- 更新前备份数据库，完成依赖、构建和迁移检查后，只重启 PolicyLens 的 RunDock 记录。
- 停用服务默认保留家庭数据，并明确显示数据目录。
- 删除家庭数据是独立的高风险操作，需要再次确认并说明备份副本。

## 最小恢复目标

只要用户保留一个可验证的加密备份及正确恢复密码，就应能在另一台具备 PolicyLens 运行依赖并由 RunDock 托管的干净 Windows 环境中恢复家庭档案、来源、核验记录、比较案例和提醒，并生成新的本机 DPAPI 包装。原电脑不可用不应阻断恢复；恢复密码遗失则无法跨机器恢复。缓存、OCR 中间文件和 AI 临时事件不属于必须恢复数据。
